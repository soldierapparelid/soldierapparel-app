# Scoped Jahit and QC form candidate

SOURCE OFF; not installed in main HTML. The controller and DOM page use the separate lifecycle bridge and its exact retained-command journal. No Firebase root listener, network call, localStorage, credentials or payroll calculation is introduced by the page. Server identity, grants, payment/dependency guards and version checks remain authoritative.

The controller supports the three Jahit actions (append, edit, delete) and eight QC actions (count append/edit/delete, single/combined inspection, single/group correction, repair). It creates request IDs and source/grant versions from the current scoped projection; form input cannot supply prices, financial totals, roles, token or host overrides. Existing rows are selected from the caller's projection. One uncertain product command blocks another form submission. Retry preserves the original command and resolves its receipt before another execution can occur. Storage uncertainty retains the same volatile command without creating a replacement ID.

All published state is frozen and scoped. Revocation, signout, callback failure and an account change clear operations, finance, product selection and volatile drafts. QC finance is denied before a fresh token or RPC. Jahit finance is fetched explicitly and invalidated after a refresh or operation; stored observations, computed count/QC earnings and advances appear separately without an invented combined payment total. A marked payment remains an observation of the original record, not verified settlement.

The DOM page writes labels and record values with textContent and constructs controls directly, without HTML interpolation. It includes product pagination, bounded tables, action-specific forms, empty-state and error messages, explicit two-step deletion, disabled submission while a product command is uncertain, and a retained-command recovery list. Operational or wage records are never added to client persistence by this page. Its callback receives the trusted controller's normalized state; substituting an unreviewed controller factory is outside the supported deployment.

Twelve controller tests compose the actual codec, bridge, atomic journal, current-account verifier, root adapter, coordinator and gateway with synthetic service/IndexedDB hosts. They exercise every form kind, isolated own wages and retained archives, role/credential/price exclusions, lost acknowledgement and reload resolution, aborted storage admission, revocation while awaiting a token, malformed projections and failure during ID generation.

Native HtmlService success values may arrive from another JavaScript realm, reorder object fields and omit nested null fields from object replies. The server gateway's separate dispatchJson method serializes only its validated scoped DTO/error/receipt. The bridge bounds that data string and rejects duplicate (including escaped) keys and excessive nesting before parsing, then makes a bounded data-only copy and applies the original binding, DTO and receipt checks. The object-copy compatibility path uses local arrays and null-prototype objects; it rejects accessors, hidden/symbol/pollution keys, sparse arrays, non-native prototypes, cycles and non-JSON values, without calling a received getter or toJSON. Lifecycle binding normalization has one explicit field order, so valid transport ordering changes cannot be mistaken for a changed caller or grant. Fourteen reply tests exercise these boundaries, serialized null retention, native-realm copies, reordered post-write refresh and malformed ACK recovery with the actual controller/bridge/server pipeline. Production native entry points must use dispatchJson; restoring missing object fields by inference is unsupported.

The prepared page ran in a native local browser against a shared synthetic gateway fixture. The subsequent editor-only Google-hosted page proof completed native HtmlService RPC, Google locks/properties and browser IndexedDB: Jahit submission and lost-ACK reload/resolution; counts across two synthetic partners; QC inspection; repair with deliberately lost ACK, reload and exact resolution; and the first partner's resulting own wage projection with stored archive values intact and foreign wages/advances excluded. A repair was applied once after recovery. The reviewed serialized gateway preserved nested null fields; both native engine and hosted proofs used the updated fixed graph. No production identity, records or database were used by these form proofs. Synthetic account/service hosts and preview property storage do not establish deployed Firebase grants or native production admission.

Other completed proofs are separate: genuine owner Google login/current-account verification, native V8/Utilities lifecycle assembly with synthetic service hosts, and nine native REST calls against one fresh synthetic node in the isolated test project, including protected anonymous access, conditional write, stale ETag rejection and lost-ACK readback. These separate proofs do not establish deployed division grants, native production admission, measured free capacity or complete cutover compatibility.

# Initialized owner access to compatible QC

The source-OFF lifecycle candidate previously required a claimed partner or QC enrollment for its ordinary quantity lane. The initialized owner has a separate grant, so using the owner's own authenticated account could not read or submit QC quantities.

The ordinary lifecycle context now recognizes only the tenant's initialized owner UID with a validated active owner grant. It provides the existing quantity-only QC projection and QC command lane. No additional enrollment is created, no worker is impersonated, and no request role or division is trusted. Owner maintenance still uses its separate owner methods. Partner sewing access and own-finance access retain their existing enrollment checks. The owner QC projection contains no wages, tariffs, private rows, roster, email or Google subject.

The identity supplied to this pure core must already be authenticated by the trusted host. Apps Script still checks Google's current account and identity continuity, reserves shared admission, fences the whole root with an ETag and confirms a durable matching receipt. The owner grant alone is not evidence that Google sign-in succeeded. Owner and ordinary QC commands share the same history chain, while receipt replay remains tied to the original UID, Google subject and grant revision.

Eight synthetic local cases cover core authorization, quantity/payroll preservation, inactive/expired contexts, caller override rejection, current-account checks, missing acknowledgement, browser journal reload, and the generated V8/JSON RPC graph. These are simulated hosts, accounts and data. This source change has not been run in the native Google proof, and earlier proof remains tied to its earlier exact bundle hash. Genuine retained enrollment, revocation, sustainable free admission, remaining owner writers and coordinated main/Rules cutover are still required. No live binding, production data write, billing linkage or service activation is included.

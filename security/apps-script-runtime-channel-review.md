## One narrow channel contract

`rpc-gateway.cjs` is an internal factory, without a public `.gs` entry. Its only request variants are `read`, `readFinance`, `execute` and `resolve`. Each accepts the transient Firebase ID token; the two command variants also accept the exact compatible append command. No request-selected project, worker, role, rate, total, host, grant or owner/QC method exists. Runtime account/grant authorization supplies the own binding; DTO validation does not authenticate it. Every response is an exact bounded own operations/finance view, a command-matched receipt, or a fixed whitelisted error. Malformed results after a possible write produce `result_unknown`; no transport success alone becomes a receipt. Runtime handle drift latches a failure, recursive dispatch returns busy, and retained token references are cleared.

`apps-script-legacy-bridge.js` calls only a future fixed `google.script.run.soldierLegacyRpc` entry with explicit success/failure handlers, one in-flight call and a finite timeout. It sends no owner OAuth token. It does not use HTTP, ContentService redirects, JSONP, URL tokens or postMessage. Error details from failed callbacks are discarded. Timeout/unknown writes retain the same command rather than minting new IDs. A local timeout cannot cancel an already submitted server call; late callbacks cannot acknowledge a stopped session, and a later exact resolution handles a possible commit.

The client checks its fixed Firebase app and Google-linked verified user object before and after awaited work. Auth-object, project, UID, grant, worker or runner changes stop the lane and clear displayed data. Initial transient failures reuse one auth subscription. The initial own DTO supplies the server-authenticated worker binding; there is no browser-side name/email role mapping. Subsequent own views must retain that exact binding. No client business-root listener, raw root, credential persistence or payroll recalculation is introduced.

Google documents asynchronous calls, separate success/failure runners, legal JSON-like argument types, and underscore-ending functions being unavailable to RPC. The prepared adapter uses that documented contract; Node callback simulation does not establish its hosted execution. ## Durable browser commands and own wages

The channel uses an isolated `soldier-apps-script-legacy-journal:v1` IndexedDB namespace and the existing atomic command store. Each journal retains the full caller/grant/worker binding and exact deployment URL, preventing a different service from adopting its commands. The fixed HTTPS store anchor is only a journal key input; no request is sent there. Old HTTP/canonical journals remain intact. Journals contain commands and receipts, without tokens, email, root data or finance views.

Preparation and the dispatched marker must commit before the RPC write. Accepted receipts must also commit before acknowledgment reaches the controller. On reload, dispatched commands resolve first; uncertain resolution may retry only the original exact command. An already accepted command is never executed again after uncertain resolution. Atomic two-tab CAS rejects same-ID payload replacement. Missing, malformed, duplicate-key, foreign-deployment or full storage fails without resetting, purging or auto-submitting retained evidence. Format bounds are 512 entries/256 KiB with space reserved for acknowledgments.

`legacy-view-client.js` is a shared pure operations/command/finance whitelist. It replaces the existing bridge's identical public operations/command normalizers and decouples the Jahit controller from its old HTTP transport. The controller remains OFF and accepts an explicit bridge factory. Own finance preserves stored fractional totals, legacy payment markers and source IDs, excludes aliases awaiting owner review, keeps unproven payment evidence explicit, and refuses a fabricated combined payout. Frozen verified QC-derived entries remain separate from stored observations; a current tariff never reprices old totals. Only own finance DTOs are returned; no raw finance collections reach this lane.

## Verification and remaining installation work

Forty-four new public synthetic tests cover the runtime bundle (11), gateway (9), shared codec (9) and browser channel/controller integration (15). The existing 29 bridge/controller cases pass after the codec extraction. The browser integration uses the actual compiled coordinator/gateway graph, fake serialized RPC callbacks and atomic fake IndexedDB: own operations/finance, lost ACK/reload resolution, timeout, failed durable preparation/dispatch/acknowledgment, signout during refresh or already submitted work, scope/runner drift, two-tab replacement, corrupt journals and payload/amount selectors. Fake browser storage/callbacks are not a native browser proof. Five additional private probe checks cover exact artifact hashes, fixed log privacy, synthetic service isolation and compatibility failure; those are not counted as public CI cases.

There is still no reviewed active public host/private identity-admission roster or finite-policy provisioning/renewal. A genuine login contract must be proved at the exact served origin without broad domain exceptions, token relays or exposing managed OAuth. Firebase's SDK validates the current document hostname against authorized domains, including subdomain matching; authorizing a whole shared Google hosting domain would materially widen the login surface and is not supplied here. HtmlService runs an iframe and allows HTTPS scripts and popups, which alone does not prove Firebase login at its actual origin. [Firebase SDK origin validation](https://github.com/firebase/firebase-js-sdk/blob/master/packages/auth/src/core/util/validate_origin.ts), [HtmlService restrictions](https://developers.google.com/apps-script/guides/html/restrictions), [Firebase Google sign-in](https://firebase.google.com/docs/auth/web/google-signin).

Ordinary legacy Jahit edit/delete, QC count/inspect/repair/edit/delete, authenticated owner corrections, fresh identity/catalog/grant reconciliation, isolated native write/recovery, free-capacity/anonymous-ingress evidence, current backup/drafts and coordinated old-link closure remain release requirements. Compatible append plus an own-wage read is insufficient to replace all division work. Production Rules remain open on the last observation, so no security claim can be made for the existing application. No new paid service or Blaze is activated to pass these requirements.

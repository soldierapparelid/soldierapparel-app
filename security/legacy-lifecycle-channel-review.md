# Scoped lifecycle browser and RPC candidate

SOURCE OFF. This separate codec, RPC gateway and HtmlService bridge are not wired to main HTML. A separate fixed lifecycle assembly now includes the server codec/gateway/runtime with the decoded Google response boundary. The older append-only assembly and journal remain unchanged. No live data, grants, Rules or billing are changed.

The browser accepts the existing own-worker Jahit operation/finance projections and an explicit QC quantity projection. QC fields include product controls, worker labels, count rows and inspection totals/notes. QC prices, payroll, advances, account email/subject, raw roots and unknown fields are rejected; QC finance is also denied locally before another token refresh or RPC. A scoped binding includes only the authenticated runtime's project, tenant, UID, division, optional worker and grant revision. Schema checks are not authentication or authorization.

Eleven commands carry request/record/product IDs, retained grant revision and operational source version, plus their exact operation-specific quantities, dates, notes and links. They carry no prices, financial totals, tokens, role or host overrides. The authoritative lifecycle service separately verifies current identity, retained grants, worker ownership, payment/dependency guards and stale versions. Local quantity/record checks are conveniences and cannot replace these server checks.

The separate gateway calls only the four synchronous runtime methods. It rejects extra caller selectors, raw roots, malformed/error/async replies and changed native method handles; exceptions after a potential write remain `result_unknown`. Transient request tokens are cleared after the synchronous call. This does not prove a deployed native lifecycle boundary.

The HtmlService bridge uses only `soldierLifecycleRpc` on the supplied native `google.script.run` runner. It refreshes the current isolated Google user's token for each call and keeps it out of storage, published views and error text. Account, app, grant, deployment and runner changes fail closed. Signout clears published data and keeps retained commands for their original scope.

Its atomic IndexedDB journal is isolated from the old append journal. It retains distinct request IDs for successive edits/deletion of the same record. A request ID cannot be reused with a changed payload. Prepared/dispatched/accepted phases and exact receipts persist; reloading resolves a dispatched or accepted request before considering the same command for execution. An accepted request is never executed again when resolution is uncertain. Lost ACK, storage abort, concurrent-tab replacement, duplicate-key corruption and signout preserve uncertainty or fail closed; no automatic reset, adoption, deletion, rebasing or broad retry occurs. The journal is bounded to 512 retained entries and 256 KiB, with 256 bytes reserved per outstanding receipt. Safe retention/renewal still needs release integration.

Twenty synthetic tests exercise the actual current-account verifier, REST root adapter, lifecycle coordinator, gateway and browser bridge together. They cover all eleven schema agreements, scoped data exclusion, local QC finance denial, count/inspection/repair/cascade and successive own edit/delete, preserved archived wages, old-command resolution after deletion, native ACK loss, two-tab conflicts, storage faults, signout and isolated/corrupt journals. Native service calls and IndexedDB are injected fixtures. These tests do not prove production grants, native CAS, durable native admission, actual hosted lifecycle IndexedDB/forms or free capacity.

Before release: wire and test forms/controllers and hosted lifecycle journal; integrate owner/archive receipt history; review ambiguous legacy flags/IDs/payment allocation; prove retained enrollment, native CAS/recovery and private/shared finite admission on isolated data; measure free capacity; reconcile backups/drafts and cut over main with protected Rules together. Remove owner-only probes and synthetic manual entry points before public division hosting. The last observed production root remained publicly readable/writable; login alone does not protect it.

# Prepared compatible legacy lane, OFF

The narrow Jahit adapter now has optional HTTP/runtime/host wiring. The actual
legacy soldier JSON remains authoritative; there is no empty-cycle migration or
v2-to-v1 identity downgrade. Owner writers still need a coordinated authenticated
cutover. This preparation does not activate a main page, data grant, live Rules,
backend or billing. The owner has declined additional service cost.

The fixed source flag is legacyOperationsEnabled, absent/false OFF. The trusted
policy must be exactly reviewed legacy-jahit-current-v1, Asia/Jakarta and
good-plus-reject. No environment, body, storage or URL can activate it. Source
configuration retains false/null and empty scope. Enabled host configuration
copies and freezes the reviewed policy and rejects malformed descriptors.

Only three paths are prepared: GET /v1/production/legacy/own and POST
/v1/production/legacy/jahit/append and /v1/production/legacy/jahit/resolve. Query,
trailing, worker/rate/role/source selectors and extra command fields are rejected.
OFF routes stop before SDK/body access. Preflight does not initialize Admin.
Reads reconstruct a bounded quantity-only own view; writes expose only matching
operationId and replayed. Shared private UID admission does not replace current
Google/retained-v2 authorization inside the root CAS. No seed/admin endpoint is
added. Cold read errors remain read-only; uncertain writes retain the same IDs.

The package contains 30 runtime sources in 35 copies, including existing pure
workflow/payroll helpers and the compatible core/adapter. Procfile, lock and SDK
pins stay fixed. Financial reader and browser controller are separate candidates;
the own-finance pure core has no HTTP/SDK/runtime registration in this increment.
The browser modules are not imported by an active main page.

The browser transport uses the existing verified-session lifecycle plus a fixed
HTTPS endpoint, fresh Google token in header, bounded duplicate-key-safe reads,
no redirects and current account/grant checks. A separate IndexedDB namespace
reuses the existing atomic CAS store. Every journal carries complete own scope
and actual legacy endpoint; tokens, legacy root JSON and financial amounts are
excluded. The journal retains exact commands/receipts up to 512 entries/256 KiB
and fails closed when full. It does not silently delete identity evidence or
resubmit old grants. Native IndexedDB/Google integration is not proved by the
synthetic fixtures.

Controller requests use one frozen request/operation pair. Lost responses keep
the same command; reload resolves retained evidence before append. A definite
preparation denial only clears an in-memory attempt after a fresh durable read
proves that exact command absent. Already durable conflicted/uncertain commands
cannot be discarded or called unsaved; explicit retirement remains future work.
No legacy global cache is hydrated. A future renderer must use textContent.

Own-finance observations preserve stored Jahit amounts and own loans/installments
without repricing. They are separate from explicit frozen workflow-v2 slip
entries. No combined payout or payment proof is manufactured. Opaque historical
deletion signatures keep affected slip evidence pending review. No business
records or private identity mapping is published with this preparation.

Meaningful synthetic tests cover guarded paths, response validation, current v2
grant/Google changes, shared quota, root commit/replay/lost acknowledgment,
immutable own journal, concurrent tabs and financial separation. Genuine RTDB
fixtures use a pinned demo project and synthetic Auth only. Results of final CI
must be recorded separately; no real Google login/IAM/platform logging or free
host deployment proof is claimed by this review.

Remaining work includes an actual no-extra-cost host and compatible transport,

draft retirement, native browser tests and reversible main cutover. Existing

# Native Google lookup response normalization

The current-account verifier deliberately rejects ambiguous response controls. A genuine owner-only hosted-login check found a successful Google account lookup whose native UrlFetch response retained gzip metadata. Its byte content had already been decoded by the host. The original verifier rejected that metadata before parsing the account. This change adds a separate SOURCE-OFF native boundary; the verifier's claims, current-account, provider-link and revocation checks remain unchanged.

`server/apps-script/decoded-google-fetch.cjs` accepts one fixed HTTPS Google accounts:lookup target bound to the reviewed project/key and the verifier's exact POST envelope. It accepts at most 64 KiB of dense native byte content, validates strict UTF-8 and a JSON object, and maps retained gzip metadata to identity only for that already decoded content. It does not decompress gzip wire bytes. Gzip magic, malformed UTF-8/JSON, unsupported encodings, duplicate control headers, redirects, wrong MIME and oversized headers/content are rejected. The original verifier still parses the same bytes with its strict duplicate-key/prototype guards and authenticates the original token through two current Google lookups. Unknown exception details do not cross this boundary.

Non-success status codes are returned without reading their body or private headers, so altered-token rejection remains Google's status and cannot become a fabricated valid account. Returned response bytes remain an internal verifier input; no public route or account DTO is supplied. OFF mode performs no host or request inspection. Endpoint controls, native method drift, reentry and malformed options fail closed.

Thirteen synthetic tests exercise the boundary composed with the unchanged actual current-account verifier, including decoded native gzip metadata, raw gzip rejection, malformed/oversized data, duplicate account keys, foreign linkage, control/header/request getters, status preservation, drift and fixed error redaction. Nine additional private synthetic tests validate the owner-only proof wrapper and its one-use allowance. Private account bindings, tokens, deployment URLs and observations stay outside this repository.

The corrected private owner-only HtmlService page subsequently completed genuine Firebase Google login and passed the unchanged verifier with this exact adapter on native Google hosts. Two current lookups of the same original token returned 200 and matched the separately reviewed owner record. A changed signature returned 400; alg=none and wrong-audience candidates were rejected locally without extra lookups. The page accepted only an exact nonce-bound, fixed technical response. No database request, managed OAuth, grant mutation, credential export or business record was used. Current disabled/revoked accounts and other worker grants remain synthetic-test coverage; this owner proof does not establish those production outcomes.

This adapter is not a production activation. It has not been added to the earlier pinned Google assembly, public gateway or main HTML. Its request/response memory bounds cannot constrain an oversized response that the native host has already buffered. It provides no shared/private production admission policy, retained worker enrollment/grant proof, native database CAS, free-capacity guarantee or main/Rules cutover. The old shared database path still requires protection together with a complete compatible workflow.

# Protected working transport and lifecycle integration

SOURCE OFF. The optional trusted `storageMigration` selects a separate fixed internal working-envelope transport; it is absent from browser/RPC requests and the public default remains disabled. The existing full-root transport and previous append bundle remain byte-for-byte unchanged.

The separate protected REST wire reads and conditionally writes only `/soldierProtectedStorageV1/working.json`, with a hard complete 2 MiB cap. No URL/path/query/cap selector enters source options or a request. Candidate size is rejected before Google verification or managed OAuth; native header/body bounds and strict JSON decoding apply to replies. Unexpected native content can consume transfer before rejection, so activation requires a validated migration and a writer fence preventing unchecked envelope growth.

The facade verifies the exact project, database, tenant, migration ID, original snapshot digest, revision, payload digest and strict stored JSON text. It returns the decoded legacy root only to the internal coordinator, which independently derives the current role and worker grant. It does not expose a root-read RPC. Lifecycle reads, counts, payroll, receipts and first-login claims retain their permission checks and atomic conditional updates.

Writes require an earlier valid working envelope and its exact ETag. They increment only that envelope's revision, serialize under the complete 2 MiB cap and use conditional PUT at the fixed working node. Photos are neither fetched nor included in the proposal. A failed or uncertain PUT clears retained transport state; confirmation and lost-ack recovery require a fresh read and the coordinator's original retained command. There is no overwrite retry or inferred success.

The lifecycle and owner-access runtimes reserve 2 or 3 bounded working replies plus the existing 10 or 14 account lookups when protected storage is selected. The separately configured recurring shared gate must use the same 2 MiB cap. The unchanged legacy lane continues to reserve 8 MiB replies. Callers cannot choose the cap.

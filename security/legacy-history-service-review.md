# Layanan riwayat tersimpan — kandidat server mati secara default

`server/production-legacy-history-service.cjs` adalah layanan baca terisolasi. Tidak ada route HTTP, runtime/main wiring, SDK initialization, Rules, writer/grant, seed, publikasi arsip, logger atau perubahan platform. Database legacy yang masih terbuka belum diamankan oleh kandidat ini. [Pembaca murni](legacy-stored-history-review.md) tetap mempertahankan nilai tersimpan tanpa menghitung ulang.

## Kontrak tetap

Factory `createProductionLegacyHistoryService({enabled,projectId,databaseURL,tenantId,snapshotVersion,database,auth,historySource,admit,clock})` mengembalikan `execute({idToken})`. OFF tidak membaca request, konfigurasi lain, SDK atau sumber. Tidak ada pilihan worker, UID, email, profil, versi, path atau source dari pemanggil. Hasil hanya `{ok:true,view}` yang lolos codec per mitra, atau `{ok:false,error}` dengan kode tetap.

Database/Auth adalah dependency SDK server tepercaya. Layanan mematok identitas app dan method, project serta origin database, dan menolak environment emulator Database maupun Auth sebelum dispatch dan pada pemeriksaan berikutnya. Reference canonical persis `authorityTenants/{tenantId}` dipatok bersama method `get/toString`; setiap snapshot **seluruh tenant** harus lolos `Adapter.validateCanonicalTenant` yang sudah ada. Grant dan keanggotaan worker pada katalog canonical diperoleh dari snapshot yang sama. API `Adapter.readGrant` saja tidak cukup karena tidak membuktikan keanggotaan katalog. Payload grant, cache browser, email-preapproval, tenant parsial dan claim owner tidak bisa menggantikan validator.

`historySource` harus berupa descriptor server tetap: `{projectId,databaseURL,tenantId,snapshotVersion,path,read}`. Path harus persis `legacyStoredHistoryArchives/{tenantId}/{snapshotVersion}`. `read()` dipanggil tanpa argumen dengan receiver asli; semua nilai descriptor dan fungsi diperiksa sebelum/sesudah await. Tidak ada fallback ke `soldier`, `soldier/produksi` atau blob yang dikirim browser. Ini kontrak adapter tepercaya, bukan implementasi SDK loader atau bukti bahwa path telah dipublikasikan/immutable. Loader nyata nanti tetap harus mematok app/origin/reference URL, membatasi penyimpanan dan memverifikasi provenance publikasi privat.

Nilai loader: `{schemaVersion:1,scope:{projectId,databaseURL,tenantId,snapshotVersion},policy:'same-stable-id-stored-history-v1',reviewed:true,immutable:true,workers:{workerId:{division,reviewed:true}},products}`. Seluruh scope harus sama dengan konfigurasi server. Metadata ini memvalidasi konsistensi sumber; **tidak memberi izin akun**. ID grant harus muncul persis dalam katalog worker sumber yang sudah direview dan division harus sama; tidak ada remapping, alias/nama/email guessing atau pengganti ID. Marker `reviewed/immutable` adalah deklarasi sumber tepercaya, bukan verifikasi eksternal yang dilakukan layanan. Arsip yang berubah atau publikasinya belum terbukti tetap menjadi penghambat aktivasi.

## Identitas dan izin sebelum/sesudah membaca

Verifier internal khusus sesi normal menjalankan `verifyIdToken(token,true)` lalu `getUser(uid)` pada awal dan akhir. UID/sub/audience/issuer terikat project; token dan UserRecord harus memiliki email terverifikasi yang sama, akun enabled, provider Google unik dengan subject/email sama, serta tanpa tenant Auth lain. Email hanya dibandingkan sebagai bagian identitas terverifikasi dan tidak memilih mitra. Field dipilih melalui own-data descriptors, termasuk class UserRecord; tidak ada token/UserRecord/email/subject yang dicatat atau dikirim.

Token harus belum kedaluwarsa dan memiliki `auth_time <= iat < exp`, nilai positif aman, tanpa auth_time/iat di masa depan. Autentikasi asli yang lebih lama diperbolehkan agar token hasil refresh dapat dipakai untuk sesi normal. Ini bukan kebijakan freshness lima menit enrollment; modul enrollment dan kebijakannya tidak diubah. Token refresh tetap tidak dapat melewati revocation, disabled account, email/subject/provider mismatch atau grant yang dicabut.

Grant canonical harus aktif, nonowner, mempunyai worker ID eksplisit, revision positif dan tepat satu module aktif `jahit` atau `potong`. ID tersebut harus terdapat persis pada katalog worker canonical dalam setidaknya satu cycle valid dan pada katalog sumber yang direview. Owner, QC-only, mixed privileges, unknown UID/worker, status sumber belum direview dan division berbeda ditolak. Riwayat tidak mensyaratkan assignment/cycle yang sedang aktif: keanggotaan katalog pada cycle inactive tetap menjadi bukti ID. Skema worker canonical saat ini menyimpan ID/nama tanpa division; division hanya berasal dari module grant eksplisit dan harus sama dengan deklarasi arsip. Nama tetap label display, tidak pernah dipakai mencocokkan worker atau menentukan hak.

Urutan: verifikasi identitas → grant/katalog valid → admission → grant/katalog yang sama tepat sebelum load → load sumber tetap dan proyeksi beku → verifikasi identitas baru → grant/katalog yang sama sesudah load → validasi waktu/scope akhir → DTO. Seluruh profil, revision dan entri katalog worker canonical harus sama, termasuk worker/division; UID/email/subject dan kronologi token juga tetap. Perubahan teramati menolak seluruh hasil. Fence ini terdiri dari pembacaan Auth dan database yang independen; bukan transaksi atomik lintas Auth/database, bukan jaminan pencabutan setelah pembacaan terakhir terdeteksi seketika, dan bukan izin yang berlaku terus.

## Batas dan pemasangan berikutnya

Sumber dibatasi 8 MiB setelah dibaca dan katalog 128 worker; codec/projector mempunyai budget record/byte sendiri. Tidak ada hasil parsial. Kapasitas SDK sebelum callback tetap membutuhkan loader/publisher yang menyimpan blob dengan ukuran terbatas. Serialization/copy tidak menjalankan object/array `toJSON`; getter descriptor terpilih ditolak. `products:null` tetap tidak tersedia, sedangkan koleksi kosong yang sudah direview tetap tersedia dengan daftar kosong. Angka lama tidak dikonversi menjadi tarif atau upah canonical, dan marker pembayaran tidak membuktikan transfer.

Kandidat belum dapat melayani akun nyata tanpa tenant canonical populated yang lolos storage/pruning, grant nyata per UID, sumber immutable privat dengan ID yang direview dan provenance yang sah, normal-session identity review, serta konfigurasi server/SDK yang benar. Keberhasilan lookup UserRecord owner bukan ID token terkini atau grant. Sebelum route read-only dipasang masih diperlukan HTTP allowlist/no-store/response validation, hosting/IAM/log controls, Rules untuk sumber privat, UI dengan binding sesi aktif dan pembersihan logout/revoke, serta cutover writer/cache/database lama. Tidak ada langkah tersebut yang diaktifkan oleh modul ini.

Tes unit sintetis: `node --test tests/production-legacy-history-service.test.cjs`. Tidak ada Google/network/database nyata, data usaha atau credential yang dipakai; fake SDK/tenant hanya menjadi fixture pengujian.

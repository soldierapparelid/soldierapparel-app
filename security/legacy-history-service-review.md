# Layanan riwayat tersimpan — kandidat server mati secara default

`server/production-legacy-history-service.cjs` adalah layanan baca mati secara default. Sambungan HTTP/runtime dan tampilan Jahit telah dipersiapkan di [review transport/halaman](own-history-transport-review.md), seluruh switch masih OFF; belum ada pemasangan utama, SDK initialization produksi, Rules, writer/grant, seed, publikasi arsip, logger atau perubahan platform. Kandidat ini belum mengamankan database legacy. [Pembaca murni](legacy-stored-history-review.md) tetap mempertahankan nilai tersimpan tanpa menghitung ulang.

## Kontrak tetap

Factory `createProductionLegacyHistoryService({enabled,projectId,databaseURL,tenantId,snapshotVersion,database,auth,historySource,admit,clock})` mengembalikan `execute({idToken})`. OFF tidak membaca request, konfigurasi lain, SDK atau sumber. Tidak ada pilihan worker, UID, email, profil, versi, path atau source dari pemanggil. Hasil hanya `{ok:true,view}` yang lolos codec per mitra, atau `{ok:false,error}` dengan kode tetap.

Database/Auth adalah dependency SDK server tepercaya. Layanan mematok identitas app dan method, project serta origin database, dan menolak environment emulator Database maupun Auth sebelum dispatch dan pada pemeriksaan berikutnya. Reference persis `authorityTenants/{tenantId}` dipatok bersama method `get/toString`; setiap snapshot **seluruh tenant** harus lolos `Adapter.validateAccessTenant`. Validator tersebut menerima tenant produksi canonical v1 yang valid atau tenant identitas v2 yang valid; dukungan baca identitas ini tidak mengizinkan perintah produksi v1 terhadap tenant v2. Grant dan keanggotaan worker pada katalog diperoleh dari snapshot yang sama. API `Adapter.readGrant` saja tidak cukup karena tidak membuktikan keanggotaan katalog dan provenance identitas. Payload grant, cache browser, email-preapproval, tenant parsial dan claim owner tidak bisa menggantikan validator.

`historySource` harus berupa descriptor server tetap: `{projectId,databaseURL,tenantId,snapshotVersion,path,read}`. Path harus persis `legacyStoredHistoryArchives/{tenantId}/{snapshotVersion}`. `read()` dipanggil tanpa argumen dengan receiver asli; semua nilai descriptor dan fungsi diperiksa sebelum/sesudah await. Tidak ada fallback ke `soldier`, `soldier/produksi` atau blob yang dikirim browser. Runtime yang dipersiapkan merakit `production-legacy-history-loader.cjs` dengan versi arsip dan bukti publikasi privat yang diberikan konfigurasi server tepercaya. Loader mematok app, method dan URL reference/snapshot, lalu memeriksa codec, scope dan digest arsip terhadap bukti tersebut. Kontrak dan loader ini belum membuktikan bahwa arsip produksi telah dipublikasikan, Rules membatasi aksesnya, atau ukuran data dalam database telah dibatasi sebelum SDK membacanya.

Nilai loader: `{schemaVersion:1,scope:{projectId,databaseURL,tenantId,snapshotVersion},policy:'same-stable-id-stored-history-v1',reviewed:true,immutable:true,workers:{workerId:{division,reviewed:true}},products}`. Seluruh scope harus sama dengan konfigurasi server. Metadata ini memvalidasi konsistensi sumber; **tidak memberi izin akun**. ID grant harus muncul persis dalam katalog worker sumber yang sudah direview dan division harus sama; tidak ada remapping, alias/nama/email guessing atau pengganti ID. Marker `reviewed/immutable` adalah deklarasi sumber tepercaya, bukan verifikasi eksternal yang dilakukan layanan. Arsip yang berubah atau publikasinya belum terbukti tetap menjadi penghambat aktivasi.

## Identitas dan izin sebelum/sesudah membaca

Verifier internal khusus sesi normal menjalankan `verifyIdToken(token,true)` lalu `getUser(uid)` pada awal dan akhir. UID/sub/audience/issuer terikat project; token dan UserRecord harus memiliki email terverifikasi yang sama, akun enabled, provider Google unik dengan subject/email sama, serta tanpa tenant Auth lain. Email hanya dibandingkan sebagai bagian identitas terverifikasi dan tidak memilih mitra. Field dipilih melalui own-data descriptors, termasuk class UserRecord; tidak ada token/UserRecord/email/subject yang dicatat atau dikirim.

Token harus belum kedaluwarsa dan memiliki `auth_time <= iat < exp`, nilai positif aman, tanpa auth_time/iat di masa depan. Autentikasi asli yang lebih lama diperbolehkan agar token hasil refresh dapat dipakai untuk sesi normal. Ini bukan kebijakan freshness lima menit enrollment; modul enrollment dan kebijakannya tidak diubah. Token refresh tetap tidak dapat melewati revocation, disabled account, email/subject/provider mismatch atau grant yang dicabut.

Grant harus aktif, nonowner, mempunyai worker ID eksplisit, revision positif dan tepat satu module aktif `jahit` atau `potong`. ID yang sama harus terdapat pada katalog sumber yang direview. Untuk tenant v1, ID juga harus terdapat dalam katalog worker setidaknya satu cycle valid; cycle inactive tetap diterima dan tidak diperlukan assignment aktif. Skema worker v1 menyimpan ID/nama tanpa division, sehingga division berasal dari module grant dan harus sama dengan arsip. Untuk tenant v2, `IdentityState.readIdentityGrant` terlebih dahulu membuktikan grant terhadap claim enrollment retained yang mengikat UID dan Google subject terkini; status approval/grant yang dicabut ditolak. Worker harus ada dalam `workerCatalog`, direview dan mempunyai division yang sama. Validasi seluruh tenant v2 juga mempertahankan provenance initialization dan registry; tidak perlu membuat cycle atau assignment produksi untuk membaca riwayat tersimpan. Owner, QC-only, mixed privileges, orphan grant, unknown UID/worker, status sumber belum direview dan division berbeda ditolak. Nama tetap label display, tidak pernah dipakai mencocokkan worker atau menentukan hak. Jalur enrollment v2 saat ini hanya menyiapkan mitra Jahit dan QC; dukungan division dalam pembaca ini tidak memberi akses Potong dengan sendirinya.

Urutan: verifikasi identitas → grant/katalog valid → admission → grant/katalog yang sama tepat sebelum load → load sumber tetap dan proyeksi beku → verifikasi identitas baru → grant/katalog yang sama sesudah load → validasi waktu/scope akhir → DTO. Seluruh profil, revision dan entri katalog yang dipilih harus sama, termasuk worker/division; jalur v2 juga membandingkan initialization dan revision katalog serta memvalidasi provenance retained di setiap pembacaan tenant. UID/email/subject dan kronologi token tetap sama. Perubahan teramati menolak seluruh hasil. Fence ini terdiri dari pembacaan Auth dan database yang independen; bukan transaksi atomik lintas Auth/database, bukan jaminan pencabutan setelah pembacaan terakhir terdeteksi seketika, dan bukan izin yang berlaku terus.

## Batas dan pemasangan berikutnya

Sumber dibatasi 8 MiB setelah dibaca dan katalog 128 worker; codec/projector mempunyai budget record/byte sendiri. Tidak ada hasil parsial. Kapasitas SDK sebelum callback tetap membutuhkan loader/publisher yang menyimpan blob dengan ukuran terbatas. Serialization/copy tidak menjalankan object/array `toJSON`; getter descriptor terpilih ditolak. `products:null` tetap tidak tersedia, sedangkan koleksi kosong yang sudah direview tetap tersedia dengan daftar kosong. Angka lama tidak dikonversi menjadi tarif atau upah canonical, dan marker pembayaran tidak membuktikan transfer.

Kandidat belum dapat melayani akun nyata tanpa tenant penuh v1 atau v2 yang valid, grant nyata per UID, sumber immutable privat dengan ID yang direview dan provenance yang sah, normal-session identity review, serta konfigurasi server/SDK yang benar. Keberhasilan lookup UserRecord owner bukan ID token terkini atau grant. HTTP fixed GET `/v1/production/history/own`, allowlist/no-store/response validation, runtime/host opt-in dan UI Jahit dengan binding sesi aktif serta pembersihan logout/revoke telah dipersiapkan; lihat [review transport/halaman](own-history-transport-review.md). Switch tetap OFF. Hosting/IAM/log controls nyata, Rules sumber privat, publikasi arsip yang direview, uji identitas dan pencabutan pada server nyata, serta cutover writer/cache/database lama tetap belum selesai. Halaman dan route yang dipersiapkan ini belum dipasang pada aplikasi utama dan tidak menutup akses database legacy.

Tes unit sintetis: `node --test tests/production-legacy-history-service.test.cjs`. Tidak ada Google/network/database nyata, data usaha atau credential yang dipakai; fake SDK/tenant hanya menjadi fixture pengujian.

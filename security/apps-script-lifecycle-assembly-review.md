# Separate fixed lifecycle Google assembly

SOURCE OFF; no main HTML or live division endpoint is installed. The earlier nine-module pure and six-module append runtime builds remain unchanged. This separate offline builder assembles twenty exact reviewed modules plus the pinned Utilities primitives. It includes current-account verification, bounded decoded Google responses, fixed-root REST, the compatible lifecycle and finance services, finite shared admission, scoped browser DTO codec and narrow server RPC gateway.

Each module hash uses UTF-8 with CRLF normalized to LF. The primitive source has its own exact hash. Dependencies are explicit, ordered and checked once; unknown or remaining requires, unsupported runtime/host globals, symlinks, path escape and oversized source are rejected. There is no hash-update/override switch. Fixed graph auditing is conservative text scanning backed by exact hashes, not a general static security proof.

The assembly evaluates without touching Utilities, OAuth, network, database, locks or properties. Its default configuration is OFF with empty binding and disabled lanes. Internal factories receive reviewed host objects explicitly; they supply no public `doGet`, `doPost`, account configuration or credential route. Offline prepared builds use fresh private directories and retain previous edited artifacts.

The lifecycle runtime now wraps only the Google identity lookups in the separately reviewed decoded-response adapter. Its fixed-root REST host remains separate within the same trusted native host. The account verifier's claims/provider/revocation checks are unchanged. The adapter was independently proved against native Google owner account responses; this composition does not itself prove live retained worker grants or database CAS.

Eight public synthetic tests execute the generated graph in an isolated V8 realm with Utilities-compatible primitives and injected service hosts. They cover exact build/OFF behavior, scoped QC and partner finance, decoded gzip metadata, count/inspection/repair/cascade, old receipt resolution, frozen historical totals, lost ACK, conditional conflict, current-account denial and shared finite allowance across factory recreation. The twenty channel tests additionally compose the actual modules through the browser journal. These tests do not prove native services or hosted forms.

An owner-only manual proof outside the repository completed genuine Google V8/Utilities evaluation of the generated graph. It passed scoped QC/read denial, count/inspection/repair/delete, superseded receipt resolution, lost ACK recovery, known conflict without retry and disabled-account rejection. Its account, REST, OAuth, lock and property hosts were entirely synthetic. It logged only fixed technical facts and made zero business data reads/writes. The runtime candidate and manual proof were saved in separate owner-project files, with earlier owner-only deployment unchanged. This proves the Google engine/Utilities composition, not native Google account/database/admission calls for this lifecycle lane. The independently proved native owner account verifier has different evidence and must not be conflated with this synthetic-host proof.

The manual proof and all owner-only auth probes must be removed before any public division deployment. Native CAS/recovery, retained enrollment/grants, durable private/shared production admission, safe renewal/retention, free-capacity evidence, compatible owner/archive integration, hosted forms/journal and coordinated protected main/Rules cutover remain release requirements.

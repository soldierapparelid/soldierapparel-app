# Batas layanan transaksi produksi

## Menu tarif owner yang disiapkan

`owner-tarif.html` dan bridge/client/jurnal khusus owner kini disiapkan dengan switch sumber OFF. Runtime menyediakan rancangan pembaca tarif satu siklus, writer `appendTariffVersion` dan resolver draf asli; tetap belum dideploy. Ketiganya memerlukan owner aktif, token segar dan body/hasil exact, berbagi batas HTTP/kuota operasional, serta mempertahankan tarif/upah lama. Paket allowlist berisi 13 sumber/16 salinan termasuk admin writer melalui closure append/resolve tarif. Detail batas data, waktu WIB, pemulihan draf dan pemasangan ada pada [kontrak menu owner](../security/owner-tariff-menu.md). Keterangan fase terdahulu tentang belum adanya UI/endpoint owner mengacu pada sebelum persiapan ini; pemilih seluruh upah owner dan koreksi sejarah masih belum tersedia.

`production-command-service.cjs` adalah batas layanan yang **nonaktif secara default**. Implementasi inti, adapter, assembly HTTP dan penghubung browser telah disiapkan, tetapi backend belum dipasang. Modul ini tidak menginisialisasi SDK, memuat credential, membuka endpoint, membaca data usaha, mengubah Rules, mengaktifkan billing, atau memigrasikan PO lama. Penggunaan tanpa `enabled: true` berhenti sebelum memanggil dependensi.

Factory `createProductionCommandService(options)` menerima dependensi server yang dipercaya: `projectId`, `auth.verifyIdToken`, `repository`, `gateway`, `admit`, dan `clock`. `execute({idToken, command})` memverifikasi token dengan `verifyIdToken(token, true)`, provider Google, email terverifikasi, UID aman, audience, issuer, dan masa berlaku. Klaim role dari token atau body tidak memberikan izin. Body hanya berisi token dan command inti; uang, PIN, profil dan workerId buatan ditolak oleh inti sebelum transaksi.

## Kontrak dependensi

- `repository.readGrant({projectId, uid})` mengembalikan `{projectId, uid, revision, profile}`. Profil administrator harus berisi boolean `active` dan `owner`, serta bila diperlukan `workerId` dan map boolean `modules`. Tidak ada fallback email/nama atau izin default. Grant lama tanpa format ini belum dapat langsung dipakai.
- `repository.readCycle({projectId, productId, cycleId})` mengembalikan `{projectId, productId, cycleId, config, wire}`. Config harus berbentuk `{revision, active: true, reviewedEmptyCycle: true, tariffPolicy: 'explicit-historical-jakarta-v1'}`. `wire` adalah envelope dari `encodeStorage`, bukan state mentah. Pengikatan produk/siklus diperiksa lagi saat transaksi.
- `repository.selectTariff({projectId, productId, cycleId, workerId, countId, workDate, selectedAt})` mengembalikan `{projectId, revision, selection}`. Worker diambil dari assignment authority, bukan payload. `selection` harus memenuhi seluruh kontrak tarif historis privat dalam [production-authority.md](../security/production-authority.md), termasuk basis waktu eksplisit pada hari kerja Jakarta. Repository harus melakukan lookup privat yang benar; fungsi ini tidak mencari tarif terkini atau menebak tarif. Lookup hanya diperlukan bagi count baru; receipt count yang sudah diterima memakai tarif bekunya.
- `admit({projectId, uid})` wajib mengembalikan boolean `true` dari pembatasan laju server. Draft kini menyediakan `production-rate-limiter.cjs` dengan kuota atomik privat yang dibagi antar-instance; pemasangan dan sizing belum dilakukan. `clock()` harus mengembalikan waktu UTC ISO dari server. Batas command adalah 32 KiB, token 16.384 karakter, envelope authority 8 MiB; batas record/revisi/node inti tetap berlaku. Maksimum percobaan luar 1–5, default 3. Batas ini belum membuktikan ukuran, durasi atau biaya runtime deployment.

Semua output repository diverifikasi bentuknya tanpa coercion, penebakan atau pembuangan kolom. Setiap percobaan luar memverifikasi ulang token, grant dan config. Untuk command count baru, tarif historis juga dibaca ulang. Pengikatan grant, config dan pemilihan tarif awal tidak boleh berubah diam-diam selama retry.

## Gateway tenant lokal dan verifikasi SDK yang masih diperlukan

Gateway wajib memiliki `projectId` yang sama, `contract: 'soldier-atomic-trust-fence-v1'`, dan `run({projectId, productId, cycleId, expectedTrust, update})`. Nama kontrak adalah deklarasi untuk adapter server yang ditinjau, bukan pembuktian keamanan otomatis. `production-tenant-adapter.cjs` menyediakan repository dan gateway yang memanggil `Reference.get/on/off/transaction` pada database yang diinjeksi. Interface mengikuti Database Admin yang mewarisi `@firebase/database-compat`. Tes Reference sintetis dan delapan tes SDK asli lulus pada [baseline CI](https://github.com/soldierapparelid/soldierapparel-app/actions/runs/37306581257). Draft sekarang menambahkan assembly dependensi, writer admin, limiter, HTTP handler dan kandidat Rules terpisah. **Inisialisasi/deployment SDK, migrasi, pemasangan dan pengujian Google Auth nyata belum selesai; seluruh factory tetap nonaktif secara default.**

`run` memanggil `update(currentWire, currentTrust)` di callback transaksi ancestor tenant yang sama dengan grant/config/tarif kanonik. `currentTrust` berbentuk `{projectId, uid, grant, cycleConfig, tariff}`; tarif bernilai `null` bila command tidak membutuhkan pemilihan baru. Salinan `expectedTrust`, cache lokal atau hasil read sebelum transaksi bukan bukti trust terkini. Transaksi biasa hanya di node authority tidak cukup bila grant dan katalog dapat berubah di node lain tanpa pagar atomik. Adapter baru menghitung ulang pemilihan tarif dari nilai tenant callback, lalu layanan membandingkan trust tersebut dengan hasil read sebelum transaksi. Tidak ada fallback transaksi produk dengan grant cache.

Factory `createProductionTenantAdapter({enabled, projectId, databaseURL, tenantId, database, maxTenantBytes?, testOnlyEmulator?})` menerima objek Database Admin yang sudah diinisialisasi oleh integrasi server tepercaya; modul tidak membuatnya. `projectId` dan URL instance harus sesuai `database.app.options`, dan `Reference.toString()` harus cocok dengan path tenant tetap. Binding produksi tetap hanya instance HTTPS resmi tanpa credential/query/path tambahan dan menolak lingkungan emulator. Tenant tidak boleh berasal dari body. Saat flag adapter tidak diaktifkan, tidak ada Reference/read/transaksi yang dibuat.

Option server terpisah `testOnlyEmulator: {host, port: 9000}` hanya berlaku untuk `projectId` berawalan `demo-`, host persis `127.0.0.1` atau `localhost`, URL app persis `https://{projectId}.firebaseio.com`, dan `FIREBASE_DATABASE_EMULATOR_HOST` persis host/port tersebut. Option tidak boleh diteruskan dari payload. Hanya dalam mode ini Reference boleh menunjukkan HTTP loopback pada path tenant tetap; URL/namespace/project/port lain ditolak. Source SDK menunjukkan bahwa `Reference.toString()` mengikuti host/protocol repo emulator; baseline SDK CI telah menegaskan bentuk itu pada versi yang dipin. Tidak ada pengurangan pemeriksaan HTTPS produksi.

Namespace baru berbentuk:

```text
authorityTenants/{tenantId}
  schemaVersion: 1, projectId, tenantId
  grants/{uid}: {revision, profile}
  ownerCommandLedger?: private createCycle receipt journal
  tariffCommandLedger?: private accepted/retired tariff draft journal
  products/{productId}/cycles/{cycleId}
    config: {revision, active, reviewedEmptyCycle, tariffPolicy}
    tariffInputs: {revision, policy, historyByWorker}
    wire: envelope encodeStorage
```

Grant UID di namespace ini menjadi sumber kanonik untuk layanan **dan Rules baru**. Jangan mengaktifkan layanan sambil mengandalkan pencabutan/grant lama di `accessControl`, mirror email, atau salinan grant per produk. Seluruh data namespace harus telah ditinjau sebelum seed server terpisah; adapter tidak menyediakan seed/bootstrap atau membaca/adopsi legacy. Kolom tidak dikenal, scope wire salah atau struktur malformed menghentikan operasi tanpa membuang sumber.

`tariffInputs.policy` wajib berisi `{version, kind: 'jakarta-fixed-local-time', hour, minute}` yang ditetapkan dan ditinjau owner; tidak ada jam/menit default. Hari kerja berasal dari tanggal command yang divalidasi, basis UTC dihitung dari jam lokal Jakarta tersebut dan tidak boleh melampaui waktu server. `historyByWorker/{workerId}/{tariffVersion}` berisi `{effectiveAt, currency: 'IDR', rate}`. Rate rupiah utuh positif; effectiveAt unik per worker. Selector memilih versi efektif paling akhir pada basis itu, dan menolak riwayat hilang/ambigu. Repository dan callback memakai fungsi selector pure yang sama. TariffVersion/basis/rate dari `expectedTrust` tidak dipakai sebagai hasil lookup. Kebijakan ini belum merupakan keputusan tarif usaha atau impor nilai pecahan lama.

Setiap perubahan administrator pada grant, config dan katalog wajib berupa transaksi ancestor tenant yang sama, memeriksa revisi sebelumnya dan menaikkan revisi terkait. Jangan menggunakan writer dari cache, transaksi grant di luar tenant, atau `set()`/`update()` pada ancestor yang sedang ditransaksikan. Versi tarif historis yang sudah ditetapkan tidak boleh ditimpa; tambahkan versi baru melalui writer yang ditinjau. Pencabutan akses harus menonaktifkan grant kanonik lebih dahulu, baru mencabut sesi Firebase Auth. Draft `production-tenant-admin.cjs` kini menyediakan perubahan terbatas grant/config dan append versi tarif; belum mencabut sesi Auth atau menyediakan UI/endpoint admin. Perubahan PO/assignment/arsip/pembayaran belum disediakan. Semua route tersebut harus siap sebelum aktivasi; adapter tidak bisa melindungi namespace dari writer Admin lain yang mengganti seluruh tenant memakai salinan lama.

Callback menyalin tenant dari nilai SDK terkini dan mengganti hanya satu envelope siklus, menjaga semua grant/config/katalog/produk/siklus sibling. Nilai SDK asal tidak dimutasi. Tenant lengkap dibatasi maksimal 8 MiB, selain batas 8 MiB per envelope; `maxTenantBytes` boleh lebih kecil. Seluruh tenant dibaca/divalidasi dan dikirim dalam transaksi: biaya, throughput, contention dan pertumbuhan snapshot belum diukur. Batas ini hanya mendukung tahap siklus baru yang terbatas, bukan bukti kapasitas seluruh sejarah aplikasi.

Callback bersifat sinkron: decode envelope → verifikasi trust → apply command → encode envelope. Bila callback dipanggil ulang oleh database, layanan mengembalikan `undefined` dan membatalkan seluruh transaksi tersebut, lalu mulai percobaan luar dengan verifikasi Auth dan read baru. Gateway wajib menghormati `undefined` sebagai abort tanpa menyimpan hasil callback sebelumnya, dan tidak boleh melakukan `set()`/fanout atau efek samping dari hasil spekulatif. Pencabutan token diperiksa kembali pada percobaan luar; pemeriksaan Firebase Auth dan commit RTDB tetap bukan satu transaksi lintas layanan.

SDK `get()` menggunakan registrasi cache sementara; gateway menahan subscription `on('value')` singkat selama transaksi, dengan batas tunggu pemanasan 5 detik dan `off()` dalam `finally`. Snapshot listener hanya mempersiapkan cache; trust tetap berasal dari callback transaksi. Tidak ada subscriber bisnis yang ditinggalkan setelah selesai/abort. Deadline pemanasan ini bukan timeout/cancellation transaksi yang sudah dikirim. Handler HTTP kini menangani deadline serta acknowledgment commit yang belum diketahui seperti dijelaskan di bawah; timeout/concurrency host dan perilaku deployment nyata belum diverifikasi.

Callback dengan tenant `null` selalu abort, tidak membuat tenant/siklus baru. Gateway melaporkan abort tersebut sebagai retryable agar layanan membaca ulang ancestor melalui repository pada percobaan luar. Cache SDK yang terus kosong berakhir dengan kegagalan terbatas, bukan bootstrap. Cold cache, cache refresh dan race dengan client Admin lain diuji pada suite SDK baseline. Transaksi memakai `applyLocally: false`; hasil sukses hanya diambil dari snapshot commit, bukan kandidat callback.

Hasil gateway hanya `{committed: false, retryable: boolean}` setelah abort, atau `{committed: true, retryable: false, wire: actualCommittedWire}` setelah commit. Snapshot hasil commit diperiksa ulang untuk receipt command yang sama. Hanya kuitansi `{requestId, revision, acceptedAt}` dan boolean `replayed` yang dikembalikan ke pemanggil. State, proyeksi, tarif, workerId, PIN, token, snapshot dan pesan error SDK tidak ikut respons; error berupa kode umum.

## Batas kesiapan pemasangan

Jalur ini hanya mendukung `sewing`, `count`, `inspect`, `repair` dan `cancel` pada siklus kosong yang telah ditinjau. Tidak ada bootstrap lewat endpoint, impor/adopsi data lama, assignment baru, edit/arsip, pembayaran, potong maklon atau koreksi periode settled. UI/jurnal/draf lama tidak diubah. Tidak ada hasil rekonsiliasi data usaha atau bukti pemulihan server dari tes sintetis ini.

Proyeksi operasional kini menyertakan `repairs` aktif dengan ID asli authority serta hubungan QC/worker/tanggal/jumlah, tanpa tarif atau aktor privat. Browser memeriksa relasi dan multiset cermin gudang; tidak menebak ID perbaikan dari hash. Pembatalan menghapus proyeksi aktif dan cerminnya, sementara record batal, snapshot serta tarif beku tetap tersimpan privat. Wire nonkosong dari versi sebelum kolom ini bukan impor otomatis yang kompatibel: bila proyeksi tidak cocok dengan inti sekarang, decoding menahan sumber tanpa memperbaiki atau membuang sejarah.

Bridge, manifest session serta FormController/FormUI/PageMode/Bootstrap Jahit dan QC baru sudah disiapkan; switch sumber tetap OFF. Sebelum pemasangan masih diperlukan inisialisasi/deployment server dan endpoint, writer administratif untuk seluruh lifecycle yang belum didukung, integrasi kandidat Rules baru bersama seluruh pembaca/penulis, pemilih upah worker untuk owner, migrasi/rekonsiliasi legacy, rollback serta sizing deployment. SDK Admin melewati Rules, sehingga Rules saja tidak memverifikasi izin pada jalur ini. Jangan memberi read pada ancestor yang berisi authority privat atau tarif mitra lain. Persiapan ini belum menjadikan aplikasi mampu menghitung upah saat aplikasi owner tutup; kemampuan itu memerlukan layanan server terpasang beserta seluruh prasyarat tersebut.

Tes lokal: `node --test tests/production-command-service.test.cjs tests/production-tenant-adapter.test.cjs`. Fixture tes ini sintetis tanpa jaringan, SDK atau data usaha. Tes Reference memodelkan CAS dengan interleaving grant/config/tarif/sibling, abort callback ulang, cold null, batas ukuran dan snapshot commit.

`security/package.json` kini memin `firebase-admin` ke `14.5.0`, diverifikasi dari release resmi dan tag sumber, untuk Node 22 atau lebih baru. Script `test:rules` pada harness emulator demo yang sudah ada juga menjalankan `production-tenant-emulator.test.cjs`. Delapan tes SDK disiapkan memakai dua Admin app independen: A dipause sebelum conditional put, B melakukan transaksi tenant kanonik, lalu A dilanjutkan untuk membuktikan CAS/retry. Reference, put, listener dan snapshot berasal dari SDK/emulator; nilai callback/hasil commit tidak dipalsukan. Fixture hanya sintetis dan namespace tenant test sendiri. Test guard loopback berjalan sebelum import SDK dan melarang konfigurasi credential nyata; credential statis `owner` khusus emulator tidak memuat ADC/key atau membuat token produksi.

Hasil baseline delapan tes SDK tersedia pada tautan CI di atas. Harness kini juga menjalankan kandidat Rules kanonik, admin, limiter dan assembly runtime; bukti setiap revisi dicatat pada CI PR. Semua suite SDK mempertahankan verifier token pengganti yang diuji terpisah: kelulusan membuktikan RTDB SDK/CAS, bukan login Google atau pemeriksaan pencabutan Firebase Auth nyata, deploy, billing, migrasi maupun pemulihan backup. Jangan memasukkan data usaha/credential proyek ke CI.

## Assembly, HTTP, limiter dan pengaturan admin pada draft

`createProductionRuntime({enabled, projectId, databaseURL, tenantId, database, auth, allowedOrigins, policy, clock?, testOnlyEmulator?})` merangkai adapter, limiter, layanan dan handler. `auth.app.options.projectId` harus cocok dengan proyek tetap; SDK diinisialisasi oleh integrasi server yang ditinjau. `policy` hanya berisi `rateWindowMs`, `rateLimit`, `deadlineMs` dan `maxInFlight`. Tidak ada identitas proyek/tenant, izin atau worker dari body. Factory tidak membuka listener, mengekspor frontend, menambah credential atau melakukan deployment.

Handler menerima POST tepat `/v1/production/commands` dengan raw JSON UTF-8 `{command}` dan satu header Bearer. Ia menolak origin yang tidak ada pada allowlist HTTPS, query, header ganda, JSON key ganda termasuk alias Unicode, prototype keys, encoding terkompresi, body >32 KiB dan envelope tambahan. Ia mengabaikan parsed `req.body`; integrasi HTTP harus memasok `rawBody` Buffer, `rawHeaders`, `headers`, `method`, `url` dan response Node-compatible. Integrasi hosting harus membatasi header dan streaming sebelum framework membuffer request. CORS bukan pengganti pemeriksaan token. Respons hanya receipt atau kode error tetap, tanpa logging body/token/SDK error.

Deadline handler menandai hasil terlambat; tidak membatalkan transaksi atau menjanjikan batas waktu respons. Handler menunggu operasi selesai sebelum `res.end`, agar tidak bergantung pada background write setelah respons Functions. Slot in-flight tetap dipegang sampai operasi selesai meskipun pemanggil terputus. Host deployment wajib memiliki timeout dan concurrency yang ditinjau. SDK rejection setelah transaksi dimulai atau kegagalan decoding acknowledgment commit menjadi `transaction_unknown`, lalu respons generic `unavailable`/503 dengan `retrySameCommand`; hasil terlambat menjadi `result_unknown`. **503/putus koneksi tidak berarti belum tersimpan.** Ulangi command, requestId, payload dan expectedRevision yang persis sama memakai token segar. Receipt tersimpan akan diputar ulang; jangan membuat ID baru atau menaikkan revisi setelah hasil tidak diketahui.

Limiter memakai transaksi atomik di `serverRateLimits/{tenantId}/{uid}`. Predikat grant kanonik aktif diperiksa sebelum membuat bucket. Grant dapat berubah setelah pemeriksaan kuota; izin bisnis tetap diperiksa dalam transaksi tenant kanonik. Jendela kuota memakai waktu server setelah warm-up, bukan waktu commit jaringan. Bucket mengikat proyek, URL, tenant, UID, window dan limit; perbedaan kebijakan, counter malformed atau waktu mundur ditahan tanpa reset/perbaikan. `lastSeenMs` mempertahankan pemeriksaan rollback lintas-instance/restart. Setiap HTTP execute, termasuk replay, memakai permit baru; retry internal service memakai permit yang sama. Hanya snapshot commit identik dengan kandidat terakhir memberi izin. Kegagalan SDK/ack limiter menolak, sehingga permit mungkin terpakai tanpa command, tetapi tidak memberi akses ekstra. Retensi/cleanup quota dan perubahan kebijakan yang ditinjau belum diimplementasikan.

Writer admin menerima `setGrant`, `appendTariff`, `setConfig`, `createCycle` dan `appendTariffVersion` seperti bentuk exact pada komentar modul. Peminta wajib Google terverifikasi dan owner kanonik aktif, diperiksa pada transaksi tenant yang sama. Binding worker harus ada dalam katalog authority yang ditinjau. Owner aktif terakhir dipertahankan. Versi tarif lama, authority beku dan data sibling tidak ditimpa. Clock tepercaya yang monoton diperiksa ulang sebelum callback; versi tarif tambahan harus berlaku setelah versi lama dan tidak sebelum waktu validasi callback. Ini bukan jaminan waktu sesudah network put. Tiga command lama tetap belum memiliki receipt admin permanen, sehingga acknowledgment yang hilang perlu dicocokkan lewat pembacaan server sebelum resubmission; jangan menganggap konflik retry sebagai kegagalan write pertama.

## Perubahan tarif owner dengan riwayat

`appendTariffVersion` adalah command owner terpisah dari lima command operasional. Bentuk exact: `{kind:'appendTariffVersion', requestId, productId, cycleId, expectedConfigRevision, expectedTariffRevision, workerId, tariffVersion, effectiveAt, currency:'IDR', rate}`. Worker wajib sudah ditugaskan dalam siklus, dua revisi harus cocok dan versi baru harus unik, berlaku lebih akhir dari seluruh versi worker sebelumnya serta tidak mendahului waktu server pada validasi callback. Rate baru positif rupiah utuh dan seluruh jumlah tugas dikali rate harus tetap safe integer. Tidak ada tanggal efektif, tarif, pekerja atau cycle default yang ditebak.

Versi tarif dan receipt disimpan bersama dalam CAS tenant. Jurnal privat opsional `tariffCommandLedger` mempertahankan canonical command string, hash, UID/requestId, target versi, acceptedAt dan receipt terbatas tanpa nominal. Validator ketiga reader/writer memeriksa versi tarif tetap sama, worker tetap ditugaskan, revisi receipt unik per siklus, expectedConfigRevision tidak melampaui config kini dan bukti tidak melampaui revisi tarif kini. Jurnal maksimal 256 entry/1 MiB dalam batas tenant, tanpa purge/reset; kosong atau rusak ditahan. Namespace requestId jurnal tarif terpisah dari jurnal createCycle; satu command harus tetap memakai ID aslinya.

Token Google terverifikasi dan owner kanonik aktif diperiksa ulang sebelum replay. Replay identik mengembalikan receipt awal setelah jam efektif lewat atau config/tarif/produksi bertambah, tanpa menambah versi lagi. Payload berubah, target/revisi stale atau penimpaan versi lama ditolak. Tariff lama, ownerCommandLedger, authority wire, snapshot dan frozenPayroll tidak ditulis ulang. Layanan count tetap memilih sejarah berdasarkan basis hari kerja Jakarta yang sudah ditinjau; versi yang belum berlaku pada basis itu tidak dipakai dan sejarah yang tidak mencakupnya ditahan. Tiga command admin lama tetap kompatibel dan belum mempunyai receipt permanen.

`resolveTariffDraft({idToken,command})` menerima command append asli setelah owner aktif diperiksa segar. Hasil accepted selalu replay bukti awal. Jika belum ada hasil, CAS tenant membuat entry retired dengan canonical body/hash, UID/requestId, target dan receipt `retireTariffDraft` tanpa nominal. Config/tarif/jadwal stale tidak menghalangi penutupan; target worker/assignment wajib tetap sah. Entry retired tidak mengklaim versi atau revisi tarif dan tidak menulis ulang data pekerjaan/upah. Validator union diterapkan oleh ketiga reader/writer. Batas gabungan tetap 256 entry/1 MiB, tanpa purge. Append body asli sesudah penutupan ditolak `draft_retired`, body berubah konflik. Perlombaan append/resolve diselesaikan atomik; hasil ditemukan saat callback direplay hanya setelah verifikasi Auth dan owner berikutnya. ID tidak digunakan ulang. Route HTTP resolver hanya menyediakan tindakan khusus ini, tanpa route admin umum.

Prinsip perubahan untuk pekerjaan berikutnya mengikuti riwayat tarif Jahit lama. Ini bukan importer seluruh model payroll lama: tarif legacy dapat pecahan, upah gudang manual merupakan sumber terpisah, tarif Potong shared per barang, dan slip memotong angsuran kasbon yang tercatat pada periodenya. Nilai lama tidak dibulatkan, dilengkapi atau dihitung ulang oleh command baru. HPP hargaJahit adalah estimasi biaya terpisah, bukan editor upah. Catatan bayarJahit lama adalah tanggal pada produk, bukan ledger nominal/worker; print/export slip tidak menandai pembayaran. Tidak ada potongan baru, saldo neto baru, pembayaran otomatis atau transaksi uang.

Owner UI/endpoint tarif baru dan koreksi tercatat pada upah historis/settled belum tersedia; koreksi masa lalu perlu jalur explicit history terpisah. Paket deployment tetap OFF dan tidak membawa writer/endpoint admin. Jurnal privat tidak boleh diisi data usaha selama read publik ancestor database live masih berlaku. Kandidat Rules menolak seluruh read jurnal; tidak ada read permission browser yang diperluas.

## Pembuatan siklus kosong oleh owner

`createCycle` memakai requestId eksplisit, metadata produk, cycleId baru, katalog worker ber-ID, assignment awal, kebijakan waktu Jakarta dan versi tarif awal privat. Jumlah seluruh assignment wajib sama dengan cutQuantity karena perubahan assignment sesudah seed belum didukung. Setiap worker yang mendapat assignment harus memiliki tepat satu tarif awal rupiah utuh positif dengan waktu efektif eksplisit yang tidak melampaui waktu server. Tidak ada pencocokan nama/email, tarif default, impor PO atau perubahan upah lama. Command ini hanya bekerja dalam tenant kanonik yang sudah memiliki grant owner; belum menyediakan bootstrap tenant atau penghubung UI owner.

Seed menghasilkan Authority revision 0, config revision 1 yang inactive/unreviewed, dan tariffInputs revision 1. Owner meninjau seed lalu menggunakan writer setConfig yang telah tersedia untuk aktivasi. Status inactive/unreviewed membatasi discovery session dan command, **bukan penghalang read pada exact projection path bagi pengguna yang sudah diberi izin oleh kandidat Rules**. Jangan menyebut seed ini ruang karantina rahasia. Siklus yang telah ada, termasuk kosong atau inactive, selalu ditolak sebagai target baru; tidak ada reset atau penggunaan ulang ID siklus.

Seed dan receipt `createCycle` disimpan dalam CAS ancestor tenant yang sama. Jurnal opsional privat `ownerCommandLedger` berisi schemaVersion 1 dan entries ber-key hash UID/requestId, hash command, canonical commandJson, ID produk/siklus, acceptedAt, hash snapshot awal dan receipt terbatas. Canonical command disimpan sebagai string agar pruning RTDB tidak mengubah input replay. Validator Admin, Adapter dan Session memeriksa jurnal terhadap product/worker/assignment awal, snapshot revision 0, kebijakan dan tarif awal yang tetap tersimpan. Tenant lama tanpa jurnal tetap diterima; jurnal kosong atau malformed ditahan. Browser tidak mendapatkan permission read tambahan, commandJson, tarif atau receipt owner.

Replay hanya berhasil setelah token dan grant owner terkini diverifikasi, dan harus mempertahankan UID, requestId serta seluruh command. Receipt awal tetap sama sesudah produksi/config/tarif baru bertambah, tanpa mengembalikan state ke revision 0. Payload berubah ditolak sebagai konflik. Callback SDK yang dipanggil ulang dibatalkan dan mengulang pemeriksaan di luar transaksi; seed spekulatif tidak dipublikasikan. Jurnal maksimal 256 entry/1 MiB dalam batas tenant 8 MiB, tidak dipurge atau di-reset. Kapasitas penuh menahan pembuatan berikutnya; ini belum kebijakan pertumbuhan seluruh histori.

Paket pemasangan terpisah disiapkan pada [deployment/README.md](deployment/README.md), tetap OFF dan tanpa deploy. Paket hanya menyediakan session/commands; endpoint admin dan antarmuka owner belum tersedia. Perubahan assignment, perpanjangan potong, arsip/reopen, pembayaran, bootstrap tenant, migrasi seluruh histori dan pemulihan draf tetap diperlukan sebelum aplikasi utama dapat berpindah penuh.

Kandidat terpisah `security/authority-tenant.rules.json` menolak seluruh browser write dan read ancestor, termasuk owner. Browser hanya membaca fixed own-profile leaves, operations/revision untuk modul operasional yang diberi izin, dan exact wage child untuk owner atau worker yang terikat dengan modul maklon. QC tidak mendapat upah hanya karena binding worker. Server authority, tarif, receipt, limiter dan metadata lain privat. Kandidat belum dipasang dan belum menggantikan Rules legacy; semua listener lama harus diubah bersama cutover. Pembaca memerlukan manifest produk/siklus yang dipercaya karena directory listing ditolak. Rules tidak dapat menyaring output Admin yang melanggar kontrak codec.

Rujukan HTTP lifecycle: [Functions tips](https://firebase.google.com/docs/functions/tips) dan [HTTP requests](https://firebase.google.com/docs/functions/http-events). Paket deploy OFF serta kebutuhan akun layanan/batas host disiapkan terpisah di deployment/. Akun layanan nyata, App Check, autentikasi nyata, anggaran biaya dan aktivasi Blaze belum dikonfigurasi/diaktifkan.

## Penghubung browser kanonik yang disiapkan

`production-session-service.cjs` menyediakan snapshot awal session melalui `execute({idToken})`. HTTP/runtime kini merangkainya pada GET tepat `/v1/production/session`, dengan bearer header, origin HTTPS, kuota dan kapasitas HTTP yang sama. Satu snapshot tenant memasok profil caller, revisi grant, manifest ID produk/siklus aktif yang sudah ditinjau dan diizinkan, serta label worker dari katalog authority tervalidasi. Pembacaan admission kuota terpisah tetap ada. Respons tidak menyediakan field tarif, history keuangan, authority, PIN, kontak, UID worker lain atau receipt. Tidak ada listing browser pada ancestor. Snapshot ini bukan izin permanen; commands dan Rules memeriksa kembali grant terkini.

Schema session tetap versi 1; validator menerima bentuk dasar lama atau tambahan tunggal opsional `workerLabels: [{productId, cycleId, workers: [{workerId, label}]}]`, dan service sekarang selalu menghasilkan tambahan itu. Setiap entri terikat ke siklus manifest yang sama. Mitra Jahit/Potong tanpa modul global hanya memperoleh label worker miliknya; owner atau modul global memperoleh katalog worker siklus yang terlihat, bukan siklus lain. Maksimum 128 worker per siklus, 1.024 label total dan 64 KiB respons; batas berlebih menahan respons, tidak memotong katalog. Label hanya untuk tampilan melalui `textContent`, bukan identitas, assignment, grant, tarif atau fallback pencocokan nama. Tidak ada perluasan Rules read karena label berasal dari GET terautentikasi.

`production-bridge.js` adalah factory browser dengan SDK Auth/Database, fetch dan IndexedDB yang diinjeksi, nonaktif secara default. Ia tidak menginisialisasi SDK atau mengubah halaman lama. Tujuan HTTPS tetap, UID terverifikasi, project/database SDK dan response session diperiksa sebelum hidrasi jurnal; perubahan tujuan saat await menahan akses. Pemanggil harus menyediakan `isCurrent()` literal true dan callback tampilan yang aman. Refresh token hanya dipakai di header, tidak disimpan atau di-log. GET/session menolak redirect, JSON duplikat/alias, tipe respons asing serta stream di atas 64 KiB atau 65.537 read. Fetch dapat mendekode gzip/br, sehingga declared Content-Length dan jumlah byte decoded dibatasi sendiri tanpa dibandingkan. [Fetch Standard](https://fetch.spec.whatwg.org/#http-network-fetch).

`production-view-client.js` memvalidasi session sebelum storage/listener dibuka. Tiga belas leaf profil tetap serta satu leaf revisi grant sendiri harus cocok sebelum membuka siklus. Pencabutan, perubahan binding/modul/revisi atau akun menutup seluruh pembaca dan membersihkan tampilan. Pembaca hanya memakai operations/revision dan upah worker sendiri pada exact path manifest; owner default dan QC tidak membaca upah. Operasi dan upah adalah listener terpisah, dengan label `independent-listeners`; tidak diklaim sebagai snapshot atomik. Belum ada pemilih upah semua worker untuk owner.

`production-command-client.js` membuat snapshot command tanpa uang/profil/worker dari body, menyimpannya sebelum fetch, memakai token segar, lalu menyimpan receipt tervalidasi sebelum menandai selesai. Pengiriman ulang mempertahankan requestId, payload dan expectedRevision. `production-command-store.js` menyimpan raw jurnal di IndexedDB pada scope project/database/tenant/UID/revisi grant/endpoint. Write membandingkan raw sebelumnya dan selesai hanya setelah transaksi IDB complete; dua tab tidak menimpa draf tanpa CAS. Perubahan scope tidak mengadopsi draf lama. Tidak ada reset, impor legacy, penghapusan otomatis, enumerasi scope lain atau credential dalam jurnal. Isi operasional tetap data privat lokal, bukan cadangan terenkripsi. Untuk browser UMD, muat client sebelum store karena store memakai validator pure client; lalu muat view dan bridge beserta codec yang dibutuhkan.

Koneksi bridge menunggu jurnal dan tampilan awal lengkap sebelum menerima command; kegagalan awal, timeout pembaca dan kegagalan sinkron membersihkan sesi. Hasil koneksi berhasil menyediakan profil, manifest, scope terverifikasi yang mencakup revisi grant, serta `workerLabels` bila ada pada session yang telah divalidasi. Scope dan label tidak memperpanjang izin sesi. Listener awal tidak membuat read operasi dan upah menjadi atomik. Bridge kini memakai retensi opt-in dengan journal exact `{read, write, lookup, acknowledge}`. Dalam satu transaksi IDB, acknowledgment memindahkan tepat satu command asli beserta receipt ke indeks arsip permanen, menghapus hanya entri itu dari jurnal aktif, dan memperbarui meter. Write biasa hanya menambah satu pending atau noop, mempertahankan seluruh sumber dan memeriksa setiap ID terhadap arsip. CAS yang menghadapi snapshot raw berulang tidak dapat membangkitkan ID diterima. Pemakaian ulang ID yang identik mengembalikan receipt lokal; payload/revisi berbeda ditahan sebagai konflik.

Jurnal aktif tetap maksimal 64 entri/256 KiB. Entri canonical v1 yang sudah memiliki receipt dan scope persis sama dapat dipindahkan satu per satu sebelum prepare berikutnya; pending dan draf legacy tidak dipindahkan atau dibuang. Arsip dibatasi 10.000 ID/64 MiB per scope. Jumlah dan ukuran terburuk envelope diterima dicadangkan untuk semua entri aktif sebelum HTTP, agar batas kebijakan tidak baru muncul setelah commit server. Batas ini tidak menjamin kuota disk browser: abort/quota/hasil penyimpanan yang belum diketahui tetap mempertahankan replay asli. Tidak ada purge/reset arsip. Factory masih mengirim satu kali per panggilan. FormController/FormUI baru menyediakan percobaan ulang manual pending dengan command asli; tidak ada retry HTTP otomatis, rebase revisi atau ID pengganti. Rekonsiliasi draf scope lama dan lifecycle seluruh halaman belum diimplementasikan.

## Pintu masuk dan formulir Jahit/QC baru

`production-page-mode.js` memilih jalur baru hanya dari konfigurasi exact tujuh field pada sumber yang ditinjau; konfigurasi default tetap `enabled: false`. `jahit-command.html` dan `qc-command.html` memuat gate sebelum kode bisnis lama. Bila switch OFF, bundle lama diaktifkan satu kali; bila ON atau konfigurasi rusak, jalur lama tetap terkunci dan tidak menjadi fallback. Tidak ada override melalui query, storage atau konfigurasi yang dimasukkan pengguna.

`production-bootstrap.js` menyiapkan app Firebase khusus dengan modul browser versi 10.12.2 yang dipin, memeriksa binding proyek/database/auth, lalu menunggu `setPersistence(auth, browserSessionPersistence)` sebelum listener atau tombol login aktif. Popup Google hanya dipanggil dari klik pengguna. Akun awal yang belum login tetap pada layar masuk; formulir menunggu akun Google terverifikasi, session kanonik, tampilan awal dan hidrasi jurnal. Perubahan akun/binding/akses atau logout setelah terikat membersihkan tampilan bisnis dan subscription sebelum layar masuk kembali dengan tombol muat ulang. Pemilihan persistence mengikuti [dokumentasi Auth](https://firebase.google.com/docs/auth/web/auth-state-persistence); popup mengikuti [dokumentasi Google sign-in](https://firebase.google.com/docs/auth/web/google-signin). Perilaku Google Auth browser nyata belum dibuktikan oleh fixture sintetis.

`production-form-controller.js` dan `production-form-ui.js` menyediakan pilihan siklus/tugas eksplisit, sewing untuk Jahit, count/QC gabungan/repair untuk QC, serta cancel dengan konfirmasi dan ID asli. Formulir Jahit mitra menampilkan pekerjaan dan upah kotornya sendiri; QC tidak merender upah, termasuk akun owner atau akun dengan beberapa modul. Tarif dan total berasal dari proyeksi server, bukan perhitungan tarif di browser; angka upah belum menunjukkan pembayaran atau potongan. Owner belum memiliki pemilih upah seluruh worker.

Input formulir biasa dan antrean pemeriksaan gabungan hanya berada di memori halaman, **belum durable**. Jurnal durable dimulai setelah command asli berhasil melalui prepare dan transaksi IndexedDB complete, sebelum HTTP; mengetik atau menambah antrean belum menyimpan draf untuk reload. Controller menahan snapshot command yang gagal/hasilnya tidak pasti agar percobaan ulang manual memakai ID, payload dan revisi yang sama. Bila prepare gagal disimpan, penahanan memori tersebut tidak menjamin pemulihan setelah halaman ditutup. Pending yang berhasil disimpan dimuat lagi hanya pada scope yang persis sama; perubahan grant atau akun tidak mengadopsi draf lama. Formulir dan gate baru tetap source OFF, tanpa deployment, aktivasi Rules atau perubahan data usaha.

Store retensi membuka database yang sama dengan schema IndexedDB versi 2, tanpa menghapus object store atau catatan lama. Upgrade menunggu transaksi sebelumnya, memicu `versionchange` dan menutup handle versi 1. Bundle lama yang meminta versi 1 kemudian ditolak. Handle yang menahan upgrade membuat koneksi baru berhenti; tidak ada fallback membuka mode penulis lama. Dua-method journal lama tetap tersedia untuk compatibility/test, dengan batas 64 entri diterima/tertunda, dan tidak dipakai oleh bridge baru.

Uji browser lokal sudah membuktikan 16 kasus dengan IndexedDB asli, termasuk CAS dua handle, pembuatan ulang store, pemisahan scope, persistence sebelum kirim, merge dua draf, respons hilang, penahanan akun lain, upgrade penulis lama, 70 catatan selesai, replay arsip, penolakan pembangkitan ID dan reservasi kapasitas. Transport server pada fixture tersebut disimulasikan; bukan uji Google atau Firebase browser nyata. Fixture berada pada `tests/fixtures/production-browser-proof.html`, hanya memakai contoh sintetis dan tidak boleh diperlakukan sebagai aplikasi produksi. Tes bridge Node merangkai HTTP/runtime dan browser client memakai SDK/IDB fault fixture; tes emulator terpisah memakai Admin SDK asli. Formulir baru Jahit/QC kini memakai bridge dan controller yang disiapkan, tetapi paket deployment, lifecycle yang belum didukung, pemulihan draf input biasa, pemilih upah owner, migrasi data serta cutover semua modul belum selesai. Kandidat Rules tetap belum dipasang.

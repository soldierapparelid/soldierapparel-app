## Batas HTTP dan pengakuan hasil

Dengan enrollment OFF, kedua host hanya meneruskan `GET /v1/production/session`, `POST /v1/production/commands`, `POST /v1/production/owner/tariffs/view`, `POST /v1/production/owner/tariffs/append`, `POST /v1/production/owner/tariffs/resolve`, dan preflight yang sesuai. Tiga route tarif memerlukan grant owner aktif yang dibaca dari tenant kanonik; claim owner/UID dari body tidak diadopsi. Route grant/bootstrap/config/ledger/pembayaran tidak didaftarkan. Raw `Buffer` dan header Node diteruskan kepada handler yang sudah ditinjau; parsed `req.body` tidak dipakai. Pada jalur Functions, batas body/header adapter bekerja **setelah** framework/platform menerima request. Tes loopback framework belum membuktikan buffering/streaming Cloud Functions atau perlindungan log platform; gap parsing upstream Functions tetap berlaku.

Kandidat native memeriksa binding host, route/origin, header dan framing sebelum menahan body atau mengambil ADC. Parser header Node dibatasi 32 KiB; aplikasi membatasi 128 pasangan dan paling banyak 32 KiB body mentah. Koneksi TCP dibatasi delapan, sementara hanya satu request dapat admitted untuk buffering atau operasi runtime. Kandidat menangani parser error dengan JSON statis dan tidak memakai body parser Functions Framework; source tidak mencatat body, token, URL atau error SDK/parser. Ini membatasi transport milik aplikasi, bukan bukti konfigurasi proxy, request/system logs, redaksi, retensi atau IAM platform sudah aman.

`hosting-rewrites.prepared.json` adalah fragment review jalur Functions untuk enam path tepat pada domain Hosting API yang sudah disetujui; tidak dipasang atau digabung otomatis dan bukan konfigurasi rewrite Cloud Run. Hosting meneruskan seluruh path/query asli, dan handler tetap menolak query. `pinTag` tidak dipakai karena dapat ikut deploy function ketika Hosting dipasang. Endpoint browser harus menyediakan exact path `https://{origin-api}/v1/production/commands`; prefix URL fungsi langsung bukan konfigurasi yang didukung bridge saat ini. Pemilihan origin HTTPS dan routing native masih perlu ditinjau. [Path asli dan perilaku pinTag](https://firebase.google.com/docs/hosting/full-config#rewrite-functions).

**Origin Hosting API harus berbeda dari origin halaman frontend**, termasuk di staging. Contoh pola yang didukung adalah frontend GitHub Pages menuju API Hosting terpisah, dengan origin frontend tepat dalam `allowedOrigins`. Bridge memakai `GET` session dengan `mode: 'cors'`, tetapi Fetch pada origin yang sama dapat tidak mengirim header `Origin`; mode tersebut saja tidak memaksanya. Adapter dan handler tetap mewajibkan `Origin` yang disetujui, sehingga **GET session pada origin yang sama belum didukung** dan akan ditolak bila header itu tidak ada. `Origin` dikendalikan browser; jangan mencoba mengisinya manual, memalsukan header, atau melonggarkan pemeriksaan Auth/origin sebagai perbaikan. Pemilihan origin terpisah dan uji browser nyata masih prasyarat aktivasi; belum ada domain atau konfigurasi live yang diubah. [Aturan Origin pada Fetch](https://fetch.spec.whatwg.org/#append-a-request-origin-header), [perilaku browser dan forbidden header](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Origin#description).

Handler mengembalikan promise operasi hingga selesai, tanpa bergantung pada write sesudah response. Deadline 25 detik mengklasifikasikan hasil terlambat; tidak membatalkan transaksi dan bukan jaminan waktu respons. Timeout host/koneksi dapat memutus acknowledgment sesudah commit. Pertahankan command/requestId/payload/expectedRevision yang sama dan ulangi dengan token Google segar; jangan mengganti ID atau menganggap 503 berarti pekerjaan belum tersimpan. Error handler tetap generik; source handler tidak mencatat body/token/error SDK. **Parser upstream Functions Framework dapat menolak JSON malformed sebelum adapter dan menulis error parsing ke log framework.** Perlindungan terhadap isi body dalam log upstream, redaksi/retensi/akses log, dan buffering host belum dipasang atau dibuktikan aman. Tes hanya memakai isi dan token contoh. Jangan mengirim credential atau data usaha ke layanan uji sebelum gap ini diselesaikan.

Pada kandidat native, body yang belum lengkap dibatasi 10 detik tanpa memanggil runtime; deadline respons 30 detik memberi error baca `unavailable` atau hasil write `result_unknown`. Setelah dispatch, disconnect atau deadline respons tidak melepaskan slot: slot tetap dipegang sampai promise runtime selesai. Write yang hasilnya tidak diketahui harus mengulang command stabil yang sama, termasuk ID/payload/revisi; timeout bukan bukti rollback. SIGTERM/SIGINT menghentikan penerimaan serta koneksi idle, lalu menunggu **socket tertutup dan `waitForIdle()` host selesai**. Tenggat keseluruhan sembilan detik dapat mengakhiri proses. `server.close()` sendiri tidak membuktikan operasi detached selesai, dan penghentian proses tidak membatalkan transaksi database atau membuktikan acknowledgment.

Pencabutan akses langsung pada kontrak kanonik memakai `grant.profile.active=false` dan perubahan revision melalui writer tenant yang ditinjau; pembaca membersihkan tampilan ketika grant tidak cocok. Server memeriksa `verifyIdToken(token, true)` pada panggilan terautentikasi. Kandidat Rules direct listener belum memeriksa metadata revocation/`auth_time`; pencabutan refresh token atau penonaktifan user Auth saja belum terbukti segera menghentikan listener yang tokennya masih valid. Tes pencabutan grant sintetis bukan uji revocation Google nyata. [Pemeriksaan pencabutan token](https://firebase.google.com/docs/auth/admin/manage-sessions#detect_id_token_revocation).

## Pembaca dan penambah tarif khusus owner

Body view tepat `{selection:{productId,cycleId}}`. Auth Google segar dengan pencabutan diperiksa, lalu satu snapshot tenant divalidasi seluruhnya. Hanya owner aktif, siklus aktif dan sudah direview yang mendapat respons. View merekonstruksi binding caller/grant/config/tariff revision, waktu server, policy Jakarta yang eksplisit, serta worker yang benar-benar mendapat assignment beserta jumlah assignment dan riwayat tarifnya. Worker lain, grant lain, wire/snapshot/receipt/ledger dan token tidak dikirim. Worker diurutkan menurut ID, riwayat menurut effectiveAt. Batas tetap: 128 worker, total 512 versi tarif, dan 64 KiB respons; tidak ada pemotongan parsial.

Body append tepat `{command}`, hanya kind `appendTariffVersion` dengan requestId stabil dan revisi config/tarif yang dilihat owner. Parser raw menolak duplicate key, field tambahan, harga pecahan/nol dan kind administrative lain sebelum Auth/quota. Admission owner menggunakan predicate owner aktif serta bucket UID dan policy yang sama dengan command/session; partner/QC tidak membuat bucket owner. Writer mengulang Auth Google dan owner kanonik dalam tenant CAS, menyimpan versi baru bersama receipt yang dapat diulang. Respons receipt tidak memuat nominal tarif, credential atau grant. Riwayat dan wire upah lama tetap dipertahankan.

Body resolve tepat `{command}` dengan append asli. Hasil `accepted` hanya replay receipt sebelumnya; hasil `retired` mencatat penutupan immutable atau replay penutupan yang sudah ada. Owner diperiksa sebelum hasil lama dikembalikan, dan penutupan baru berada dalam CAS tenant yang sama dengan append. Config atau jadwal stale tidak menghalangi penutupan. Jika penutupan dahulu menang, append identik yang datang terlambat ditolak sebagai `draft_retired`; jika append menang dahulu, versi tarif tetap dipertahankan. Payload berubah tetap konflik. Penutupan tidak menulis rate, config, wire, frozenPayroll atau snapshot.

Ketiga route berbagi gate inFlight dengan command/session. View gagal/terlambat hanya memberi error baca; append/resolve dengan acknowledgment tidak pasti tetap membutuhkan pengulangan command yang persis sama, bukan ID/revisi/payload baru. Belum ada endpoint untuk koreksi upah lama, grant, createCycle, setConfig, pembayaran, data lama, atau seed tenant pertama. Source tetap OFF dan seluruh route ini belum dipasang live.

## Kontrol pencabutan akses yang dipersiapkan

`identityRevocationEnabled` adalah opt-in sumber terpisah, default OFF; flag yang tidak ada juga OFF. Parent `enabled` tetap wajib aktif. `POST /v1/production/owner/access/revoke` dan `POST /v1/production/owner/access/resolve` hanya terdaftar saat opt-in tersebut aktif. `resolve` hanya mengonfirmasi receipt pencabutan yang sama dan tidak menulis. Deadline/disconnect/ACK hilang tetap memerlukan command yang sama; HTTP menunggu settlement dan mempertahankan slot. ## Riwayat upah sendiri yang dipersiapkan

`legacyHistoryEnabled` adalah switch sumber terpisah, default/absent OFF. Jika diaktifkan pada salinan deployment privat, `legacyHistoryArchive` harus mempunyai tepat snapshotVersion dan publicationProof yang diperiksa terhadap scope server tetap. Proof tetap di backend privat; jangan menerbitkan proof, arsip, digest sumber privat atau konfigurasi produksi berisi proof ke GitHub/frontend/CI. Source publik hanya memuat null. Flag OFF menolak GET `/v1/production/history/own` sebelum body/SDK. GET/preflight tidak menerima body, worker, UID, tenant atau versi arsip dari caller.

Runtime merangkai loader fixed private archive, service riwayat dan permit UID yang sama. Loader memeriksa digest arsip terhadap proof independen; service mengulang Google Auth/current record dan grant/katalog retained sebelum mengembalikan data. Endpoint mengembalikan hanya view yang dinormalisasi ke scope server, dengan field tersimpan milik worker pemanggil. Tidak mengubah data, mencatat pembayaran atau menghitung ulang total lama. Owner/QC tidak memakai endpoint own-partner ini.

Bridge memakai token segar di header, response streaming yang dibatasi, tanpa redirect, query, localStorage, jurnal atau write data riwayat. View harus cocok dengan UID/worker/divisi/revision session yang diverifikasi. Perubahan akun/izin membatalkan request dan membuang balasan terlambat. Tombol Jahit membaca riwayat hanya atas klik pengguna; hasil lama tidak digabung ke upah pekerjaan baru. Halaman mode canonical dan semua switch server masih OFF. [Review transport/halaman](../../security/own-history-transport-review.md) mencatat bukti dan gap rilis. Ini belum migrasi produksi aktif atau pemasangan aplikasi utama.
